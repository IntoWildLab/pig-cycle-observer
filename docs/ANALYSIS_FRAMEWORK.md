# Pig Cycle Analysis Framework

本文记录当前可迭代的猪周期分析方法论。它不是固定金融定律，也不代表当前系统已经实现全部分析能力。具体窗口、阈值、权重和阶段定义应根据真实历史数据及校准结果持续调整。

## 1. 最终分析链

```text
产业事实数据
  → 时间序列趋势
  → 趋势特征
  → 周期状态
  → 公司盈利
  → 市场定价
  → 投资机会观察
```

- **产业事实数据**：回答官方数据实际记录了什么，保留日期、来源和修订轨迹。
- **时间序列趋势**：把不同天然频率的数据按各自时间尺度组织起来，不制造虚假精度。
- **趋势特征**：识别方向、持续性、速度、拐点和指标之间的组合关系。
- **周期状态**：用可解释、可校准的语言描述产业所处位置及迁移方向。
- **公司盈利**：分析产业变化如何通过公司价格、成本、出栏和效率转化为盈利。
- **市场定价**：判断股票或 ETF 已经提前反映了多少产业和盈利变化。
- **投资机会观察**：综合支持证据、反向证据、风险和失效条件，形成辅助观察而非机械交易指令。

## 2. 原始产业指标

当前重点指标包括：

| 经济含义 | 指标 |
| --- | --- |
| 长期产能 | 能繁母猪存栏 |
| 中期预期与补栏意愿 | 仔猪价格 |
| 当前商品价格 | 生猪价格 |
| 行业盈利环境 | 猪粮比 |
| 成本环境 | 玉米、豆粕、育肥猪配合饲料 |

这些指标不能简单相加。它们反映不同时间尺度、传导环节和经济含义，领先或滞后关系也可能随政策、疾病和生产效率变化而改变。

## 3. 趋势特征候选

### 已实现的 Trend Feature Layer v0

当前架构已形成：

```text
Fact Layer → Trend Feature Layer → future Cycle Layer
```

`src/pig_cycle/trend.py` 是无 SQLite、无 HTTP、无 LLM、无副作用的纯计算层。它接收 `MoaWeeklyRecord` / `SowMonthlyRecord`，返回 frozen `NumericTrendFeatures`。当前支持：

- MOA：`piglet_price`、`live_hog_price`、`corn_price`、`derived_pig_corn_ratio`；
- Sow：按单一 `SowSourceType` 隔离计算 `sow_inventory`，不同来源不混合。

已实现特征包括 observation count、latest/previous、最新相邻变化及百分比、窗口起点、累计变化及百分比、末端连续上涨/下降变化次数、末端方向、观测键、真实间隔单位和 irregular interval 标记。streak count 严格表示从末端向前的连续同方向**相邻变化次数**，不是记录数、周数或月数。

Trend v0 只提供机械特征，不判断六阶段，不输出“去产能”“底部形成”“趋势确认”、置信度、阈值或投资信号。

### Snapshot whole-window 与 Trend terminal streak

Snapshot 的“所示记录方向”归纳整个当前展示窗口内全部相邻变化：全部同号时显示连续上升或连续下降，全部为零时显示持平，否则显示混合。Trend 的 `latest_streak_direction` 与连续计数只从序列末端向前统计同方向相邻变化。

例如生猪序列 `10.48 → 11.35 → 11.50 → 11.45 → 11.22 → 11.13`：Snapshot whole-window direction 为“混合”，Trend terminal streak 为 `DOWN`、down count 为 `3`，同时累计变化约为 `+6.20%`。这些结果描述不同维度，可以同时成立。未来 Snapshot 即使消费 Trend Layer，也必须分别标注两种语义，不能直接用 terminal streak 替换当前 whole-window helper。

### 尚待验证的候选

以下窗口和特征均为候选，必须经过历史验证后才能形成稳定规则。

周度指标可研究：

- 4 周、8 周、12 周变化；
- 连续上涨或下降周数；
- 累计变化和趋势斜率；
- 加速或减速；
- 是否止跌、止涨；
- 是否创阶段新高或新低。

月度指标可研究：

- 3 个月、6 个月变化；
- 环比和同比；
- 连续扩张或去化月数；
- 累计变化；
- 去化或扩张速度。

“当前值”只是事实。真正用于判断的是变化方向、持续性、速度、拐点和指标组合关系。周度与月度数据应保留各自天然频率，不应用插值制造并不存在的日度精度。

当前继续暂缓硬编码 4/8/12 周窗口、window high/low 的解释、斜率、加速/减速、拐点、止涨/止跌、周期阶段阈值、置信度和投资信号。原因是历史长度、语义和校准仍不足，候选假设不能提前固化为正式规则。

## 4. 周期状态框架 v0.x

当前候选解释框架如下：

### 🔴 下行期

- 猪价下降；
- 猪粮比走弱；
- 仔猪偏弱；
- 产能仍高或刚开始下降。

### 🟠 产能去化期

- 行业盈利承压或亏损；
- 能繁母猪持续下降；
- 补栏意愿偏弱。

### 🟡 底部形成期

- 产能已经去化一段时间；
- 仔猪开始止跌；
- 生猪价格或猪粮比出现企稳迹象。

### 🟢 上行期

- 前期供给收缩开始兑现；
- 生猪价格改善；
- 猪粮比改善；
- 行业盈利修复。

### 🔵 高景气 / 扩产期

- 猪价和盈利较好；
- 仔猪活跃；
- 补栏和产能开始恢复。

### 🟣 顶部风险期

- 当前猪价或利润可能仍好；
- 母猪等产能已经扩张一段时间；
- 未来供给压力逐渐积累。

这是 **v0.x 候选语言**，不是最终定论。未来可以合并或拆分阶段、调整定义和权重、改为得分制或阶段概率，并增加阶段迁移方向与置信度。

## 5. 阶段迁移比阶段标签更重要

未来系统不应只输出“当前是底部形成期”，还应尽量说明：

- 当前阶段及持续时间；
- 当前位于阶段的前段、中段还是后段；
- 方向正在改善还是恶化；
- 最可能迁移到哪个阶段；
- 支持证据和反向证据；
- 判断置信度。

目标形式例如：

```text
当前：🟠 产能去化期
位置：后段
方向：改善
候选下一阶段：🟡 底部形成期
置信度：中等
```

不应因单周异常数据频繁切换阶段。未来需要评估连续确认、滞回机制或其他防抖方法，但具体参数仍须历史校准。

## 6. 公司盈利层

行业环境与公司盈利必须分开，不能使用“猪价 - 饲料价格 = 公司利润”。更合理的优先逻辑是：

```text
公司实际或披露销售价格
  - 公司完全养殖成本
  ≈ 单位盈利能力代理
```

未来公司层可研究：

- 完全成本及其变化趋势；
- 销售均价；
- 出栏量；
- 养殖效率；
- 业务结构；
- 成本领先程度；
- 猪价变化时的盈利弹性。

行业玉米、豆粕和饲料价格用于观察行业成本趋势。只有缺少公司数据时才可作为代理，并必须明确注明代理关系、降低置信度，不能冒充公司真实完全成本。

不同公司披露的“完全成本”“销售均价”等指标，在直接横向排名前必须检查口径可比性。可能影响可比性的因素包括：

- 成本定义以及是否包含特定折旧或费用；
- 自繁自养与外购仔猪结构；
- 出栏体重；
- 产品结构和地域结构；
- 报告期间；
- 公司披露口径变化。

如果口径无法可靠统一，可以比较同一公司自身的时间趋势，但不得假设不同公司的绝对数值完全可比。未来公司盈利层应记录指标来源、报告期间、指标定义或口径、是否适合横向比较，并在必要时给出置信度。行业玉米、豆粕和饲料仍然只是成本环境指标或低置信度代理，不能替代公司真实成本。

## 7. 市场预期层

最终需要重新连接 V1 的股票和 ETF 数据。重点不只是技术分析，而是回答：**市场是否已经提前交易了产业变化？**

候选观察包括：

- 20、60、120 日收益；
- 相对养殖 ETF 强弱；
- 相对同行强弱；
- MA5、MA10、MA20 等趋势信息；
- 股价是否已经大幅领先产业数据；
- 后续经过验证的合适估值指标。

可能出现的解释情形：

- 产业改善、股票尚未反应：可能存在预期差；
- 产业改善、股票开始走强：可能形成右侧确认候选；
- 产业刚改善、股票已经大幅上涨：产业逻辑可能成立，但市场可能已提前定价。

这些只是分析情形，不是固定买卖规则。

## 8. 投资机会雷达的目标形式

以下仅展示未来输出结构，不是当前可执行算法：

```text
产业周期：🟡 底部形成期
迁移：🟠 → 🟡，方向改善

支持证据：
- 母猪连续去化
- 仔猪止跌
- 猪价企稳
- 猪粮比改善

反向证据：
- 去化速度放缓
- 猪价尚未明确上行

公司：牧原、温氏、新希望、神农等
公司盈利：销售价格、完全成本、单位利润代理、成本趋势

市场：股价趋势、相对 ETF、市场是否提前反映

综合：产业位置、公司盈利弹性、市场确认程度、潜在预期差、
风险、失效条件和候选观察位置
```

最终输出应是投资辅助观察，而不是机械买卖指令。

## 9. 历史校准与验证原则

正式固定阈值前，应尽可能回看过去的完整猪周期，研究：

- 母猪拐点通常领先猪价多久；
- 仔猪价格是否具有稳定的领先或确认作用；
- 猪粮比在什么阶段最有意义；
- 饲料成本变化如何影响行业和公司盈利；
- 不同周期中的领先关系是否稳定；
- 股票通常领先产业基本面多久；
- 公司成本差异如何影响盈利弹性；
- 哪些指标在特殊事件或政策阶段可能失真。

现阶段不应凭主观印象规定“母猪下降 X 个月等于某阶段”或“变化 X% 等于买入”。阈值、确认周期和权重应来自历史校准，并保留反例。

历史回看、校准和未来回测必须采用 **point-in-time / as-of** 思维。在判断历史某个日期的周期状态时，只能使用当时已经正式发布、当时实际可获得的数据。例如，一项属于 6 月的月度数据如果直到 7 月 15 日才发布，就不能用于模拟 7 月 10 日的判断。

历史分析必须区分：

- 数据所属日期，如 `collection_date` 或 `month`；
- 官方 `publish_date`；
- 后续发布的修订。

不得使用后来发布或后来修订的数据美化历史判断。当前数据层已经保留 `publish_date`、`source_url` 和 processed source 等语义，未来历史分析应利用这些信息避免 look-ahead bias（前视偏差）。

Trend v0 已支持按 `as_of` 对官方 `publish_date` 做最后一道过滤，从而阻止晚于判断时点发布的当前记录进入计算。但当前 storage 只保存当前有效业务版本，不能完整重建已被后续修订覆盖的旧版本。完整 point-in-time revision history 属于未来独立存储能力，不能把当前 `as_of` 过滤描述为完整历史复原。

### Historical calibration 的 point-in-time 前置条件

正式 historical calibration、lead-lag、阈值研究或 backtest 前，计划先保留现有 current effective tables，并增加独立 append-only revision history。历史读取必须明确选择两种不同问题之一：

- **official-availability as-of**：按官方 `publish_date` 判断理论上已经公开的数据版本；
- **system-knowledge as-of**：按系统首次成功观察版本的 `observed_at` 和历史保存判定，重建系统当时实际知道的 effective state。

业务所属日期、官方发布日期和系统观察时间不得互相替代。历史回填记录尤其不能因为官方发布日期较早，就假装系统当时已经掌握。未来链路应保持为 `revision storage → point-in-time reader → domain records → Trend pure functions`：Storage 负责版本选择和冲突处理，Trend 继续只负责机械特征。

revision tables、point-in-time reader 和两种 as-of 目前均尚未实现。开始正式校准前还必须具备 append-only revision persistence、可靠 `observed_at`、baseline provenance、conflict / order-unknown 处理和防止 look-ahead 的回归测试。当前 `processed_sources` 会跳过已处理 URL，因此同 URL 原地修订仍是明确的检测边界，不能通过高频重复请求来掩盖。

## 10. 模型设计原则

第一版优先采用：

- 透明规则；
- 可解释、可追溯；
- 权重可调整；
- 同时展示支持证据和反向证据；
- 输出置信度。

系统不得为了每个观测期都有阶段标签而强制分类。以下情况应允许返回“证据不足”“低置信度”或“指标冲突”：

- 历史窗口不足；
- 关键指标缺失；
- 不同来源之间存在重要冲突；
- 特殊事件导致指标暂时失真；
- 支持证据与反向证据接近。

模型应优先诚实表达不确定性，而不是制造虚假的确定结论。不同官方来源出现差异时，应保留各自来源和统计口径，不应默认简单平均。

暂不急于使用复杂黑箱机器学习。完整独立猪周期样本有限，并存在政策、疾病、生产效率提升等结构性变化。未来数据足够时，可以增加统计或机器学习模型作为第二套参考，与透明规则模型比较，而不是直接替代可解释基线。

## 11. 当前北极星

数据不是最终目标，阶段判断也不是最终目标。整个系统最终必须帮助回答：周期在哪里？正在往哪里走？哪些公司真正更可能盈利？市场已经提前交易了多少？目前值得重点观察什么？主要风险和失效条件是什么？
